# Legal Timekeeper 2.0

Time entry for legal work at `https://jtbarnespllc.com/lab/timekeeper/app/`. It replaced the original My Legal Timekeeper (jasontbarnes.com/mylegaltimekeeper) on November 6, 2026.

## How it works

- **Static app, no server.** Plain HTML, CSS, and JavaScript in `docs/lab/timekeeper/app/`. It is not generated by `build/build.py`, so edit those files directly.
- **On-device first.** Entries are saved in the browser (`localStorage`, key `tk.v2.entries`). Everything works with no sign-in and offline.
- **Optional Microsoft sign-in.** OAuth 2.0 authorization code flow with PKCE (`js/auth.js`), written directly against Microsoft's endpoints. No Microsoft library and no client secret are used.
- **Sync through the user's own OneDrive.** The file `timekeeper-data.json` lives in the app's private folder (OneDrive > Apps > MyLegalTimekeeper, named after the app registration). The app requests only `Files.ReadWrite.AppFolder`, which reaches that one folder. Merging is last write wins per entry, and deletions are kept as markers so they spread to other devices. Writes use the file's eTag, so two devices saving at once never overwrite each other (`js/sync.js`).
- **The firm never receives entries.** They go only between the browser and Microsoft.

| File | Purpose |
|---|---|
| `index.html`, `app.css` | Interface (Lab design tokens, self-hosted fonts) |
| `js/config.js` | Client ID, sign-in authority, scopes, version |
| `js/core.js` | Hours parsing, rounding, export, import, merge (no DOM) |
| `js/auth.js` | Microsoft sign-in |
| `js/sync.js` | OneDrive sync |
| `js/app.js` | Screens, voice conversation, settings |
| `sw.js` | Offline support (network first, so updates arrive on the next visit) |

When you change any app file, raise `VERSION` in `js/config.js` and `CACHE` in `sw.js` together.

## One-time Microsoft setup

Done on November 6, 2026: app registration **MyLegalTimekeeper**, client ID `cfc6cf5e-cfbf-45a4-969c-14481512cb69`, all Microsoft account users. If `CLIENT_ID` is ever blank, the app runs on-device only and hides sign-in.

1. Go to **entra.microsoft.com** and sign in as the firm's administrator.
2. Open **Identity > Applications > App registrations > New registration**.
   - **Name:** `Legal Timekeeper`. This name appears on the Microsoft consent screen and becomes the OneDrive folder name.
   - **Supported account types:** *Accounts in any organizational directory and personal Microsoft accounts*.
   - **Redirect URI:** platform **Single-page application (SPA)**, value `https://jtbarnespllc.com/lab/timekeeper/app/` (exactly, with the trailing slash).
3. Click **Register**, then copy the **Application (client) ID**. It is not a secret.
4. **API permissions > Add a permission > Microsoft Graph > Delegated permissions:** add `Files.ReadWrite.AppFolder`. You may remove the default `User.Read`, since the app does not use it. Do not create a client secret or certificate.
5. **Branding & properties:**
   - Home page: `https://jtbarnespllc.com/lab/timekeeper/`
   - Terms of service: `https://jtbarnespllc.com/legal/`
   - Privacy statement: `https://jtbarnespllc.com/legal/privacy/`
   - Logo: `brand/timekeeper-logo-240.png`
6. Put the client ID in `docs/lab/timekeeper/app/js/config.js` (`CLIENT_ID: '...'`), raise the version, and publish.

### Optional: publisher verification

Personal Microsoft accounts and accounts in the firm's own tenant can sign in without this step. Many organizations allow their users to approve only apps from a **verified publisher**, so people signing in with another firm's work account may be blocked until the app is verified. Verification is free:

1. Join the Microsoft AI Cloud Partner Program.
2. Verify the domain `jtbarnespllc.com` in Entra.
3. Add the Partner ID under **Branding & properties > Publisher verification**.

## Old address

`jasontbarnes.com/mylegaltimekeeper/` (repository `mylegaltimekeeper`) and `jasontbarnes.com/MyLegalTimekeeper/` (folder in `jasontbarnesesq.github.io`) now hold a forwarding page.

- If the browser still has entries from the original app, the page offers to hand them to the new app. The new app checks the sender's origin before accepting them.
- The page also offers a download that the new app can import.
- A replacement `service-worker.js` clears the original app's offline copy on devices that installed it.
